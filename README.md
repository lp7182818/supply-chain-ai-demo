# 供应链采购分析与合同风险审查演示

本项目是面向供应链场景的**采购数据分析 + 合同风险审查**演示工具：用网页上传练习用 Excel / 合同文本，完成台账查询与一次性合同要素提取。

入口文件为 `project_app.py`。侧边栏可在「采购数据分析」与「合同要素提取」之间切换。

## 为什么做这个

我做过多年采购和 ERP 实施，台账对不上、合同条款对不齐，基本是日常。Excel 里订单和供应商各一张表，编码对不上就得一行行翻；合同总价、明细、付款条件散落在不同段落，人工审查又慢又容易漏。想用一个能上手的小工具，把「先把数对上、再把条款标出来」这件事做出来给自己看，也给面试官看：不是空转大模型，是把现场核对过的痛点接到页面上。

## 功能说明

### 1. 采购数据分析

- 上传 Excel（`.xlsx`），将工作表读入内存 SQLite（不落盘）。
- 四个查询（下拉框一次只看一种）：
  1. 某个日期之后的订单
  2. 每个供应商下单笔数与总采购金额（表格 + 柱状图）
  3. 按供应商编码拼接订单与供应商（INNER JOIN）
  4. 检查孤儿数据（订单有编码、供应商表没有；或供应商有档案、订单从未出现）

约定表结构：Excel 中需有「订单」「供应商」等工作表，并包含演示脚本所用字段（如下单日期、供应商名称/编码、采购数量、单价等）。

### 2. 合同要素提取

- 上传合同 **txt** 文件（只读解码，不改写原文件）。
- 点击「开始提取」后调用 DeepSeek，一次性输出 JSON。
- 页面分三块展示：
  - **基本信息**（供应商、合同总金额、交货地点、付款条件、签订日期）
  - **物料清单**（名称、规格型号、单价、数量）
  - **风险清单**（什么风险、在合同哪个位置、为什么）

本模块不做多轮追问、不保存对话历史。JSON 解析失败时最多自动重试 1 次。

## 技术栈

- Python
- Streamlit（网页界面）
- pandas（读 Excel、结果表格）

- DeepSeek API（合同提取；代码通过 OpenAI 兼容客户端调用）

## 快速开始

Python 3.9 及以上即可。

1. 安装依赖：

```bash
pip install streamlit pandas openpyxl requests openai
```

2. 在 `project_app.py` **文件顶部**的 `API_KEY` 变量中填入你的 DeepSeek 密钥。页面不会展示密钥；请勿把真实密钥提交到仓库或打印到日志。
3. 启动网页：

```bash
python -m streamlit run project_app.py
```

浏览器打开提示的本地地址即可使用。

## 数据声明

本仓库及演示过程中使用的 **所有 Excel 与合同文本均为虚构练习数据**，不包含真实企业名称、真实合同条款或真实业务信息，仅用于课堂/自学演示。

## 踩过的坑

- **空 Sheet 把 SQL 打崩。** 现象：Excel 里有一张没数据的表，导入后查询直接报错。发现：第一次跑查询 1 就炸了，顺着 pandas 看是空表被写成了 SQLite 里的空表。处理：导入时跳过「0 行或 0 列」的 Sheet，并在页面上黄条提示。
- **「供应商名称」列里装的其实是编码。** 现象：按列名 `供应商名称 = 供应商名称` 去做 JOIN，对不上或对错人。发现：打开单元格才看见订单表该列存的是供应商编码。处理：JOIN 改成 `订单.供应商名称 = 供应商.供应商编码`，查询结果里把该列改叫「供应商编码」，避免自己再看走眼。
- **孤儿单差掉 1212 元。** 现象：序号 11 的订单（订单编号 2024091811，供应商编码 ZHAOSHIGUER）在订单表里有、供应商档案里没有；金额是 101×12=1212 元。发现：查询 4 的孤儿表翻出这一笔；对照查询 3，INNER JOIN 后总金额从 5612 变成 4400，差的正好是这 1212。处理：查询 4 分成「订单孤儿」和「供应商孤儿」两张表。INNER JOIN 时这笔 1212 元凭空消失——这就是主数据缺档在财务上的真实代价，不是「少一行记录」那么轻。
- **合同总价和明细差 20,500。** 现象：提取出来的合同总金额，和物料清单数量×单价加总对不上，差额正好 20,500。发现：按提示词要求把每条明细算式列出来再求和，才对上这个缺口。处理：提示词强制「必须列出完整算式」，差额进风险清单，而不是只信合同封面那个总价。
- **风险清单漏报第 4 条。** 现象：合同里明明还有一处风险，模型只标了前几条。发现：对照原文人工复核时漏了第 4 条。根因：提示词核对清单当时只写了供应商名称是否一致、总金额是否等于明细、付款条件是否明确，清单外的点模型就不报。处理：承认风险点绑在提示词清单上，并在「局限」里写明必须人工复核。

## 局限

- 合同文件**仅支持 txt**，不支持 Word、PDF 等格式。
- 合同为**一次性提取**，没有多轮对话、追问或会话记忆。
- 风险点依赖提示词清单，清单外的问题容易漏报，这不是完整法律审查。
- 模型输出可能有遗漏或误判，**结果必须由人工复核**后才能作为任何实际依据。
